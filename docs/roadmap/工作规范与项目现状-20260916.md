## 3. 强制工作规范（AGENTS.md）

### 3.1 强制规则

- **亲测有效才能提交**：任何改动必须自测通过、看到真实结果后才可提交/交付，禁止"应该没问题"式提交。
- **JSX/JS 提交前必须 eslint src 过（exit 0）**：build 不检查未定义标识符，no-undef 是拦住 ReferenceError（如 RUN_STATUS_META）的唯一静态门。
- **确认意识**：更换/上传/删除类变更性交互必须有明确确认步骤，不得静默生效。
- **不回退用户否决过的设计**：底部长驻操作按钮＋提示、缺稿角标＋筛选、"多此一举"的装饰。
- **提交与节奏**：每次修改后必须 git commit 备份；大改先升 package.json version 再 build:exe；每完成一步先与用户确认。

### 3.2 自测通道（已验证可用）

- 前端 **localhost:5173**、后端 **localhost:3001**；dev 启动 node scripts/dev.cjs（后台）。
- 数据验证一律走 **HTTP fetch**（/api/tasks、/api/drawings?task_id=N、PATCH /api/tasks/:id）；禁止 shell node 直连 better-sqlite3（ABI 不匹配报 ERR_DLOPEN_FAILED）。
- 浏览器 E2E：Puppeteer（puppeteer-core）＋系统 Chrome，headless:'new'＋独立 userDataDir（放 %TEMP%，勿放项目根）。
- 自测临时文件/脏数据必须清理；禁止 git add -A（会误捡 _*.cjs、_chrome_t*、测试上传等残留）。
- 测试改写数据后必须恢复用户真实数据。

### 3.3 环境坑（勿重试）

- computer_use_tool 的 bu/cu plane 本环境不可用；GUI 自测走 Puppeteer / 便携 Chrome（D:/Chrome131_AllNew_2024.11.15/App/chrome.exe）＋ Playwright connectOverCDP。
- Edit 工具对 CRLF 文件报 Native execution failed：先转 LF 再 Edit；同一文件同一回合只发一条 Edit（多条只有最后一条落盘）。
- AI 侧 bash PATH 缺 PortableGit usr/bin：先 export PATH 再跑 npm/ls/head 等命令。
- git 写嵌套分支引用（.git/refs/heads/x/y）会静默失败：推荐 git push origin sha:refs/heads/分支 绕过；commit 后只用只读命令验证。
