## 四、REQ-019 开发计划

### 4.1 需求理解

「人员预设」（PeopleEditor）中已存在人员的姓名目前为纯文本展示、无编辑入口；姓名录入错误或需改名时只能删除重加，且删除仅移除预设、历史引用断关联。期望姓名支持重新编辑（即改即存），重名校验与新增一致；**改名后同步更新全站引用**（用户已拍板）。

### 4.2 现状核对（2026-09-09 读码确认）

- `src/components/settings/PeopleEditor.jsx`：people-row 内姓名为 `<span className="people-name">{p.name}</span>` 纯文本 ✓
- 角色支持 + 添加 / 标签 × 删除、人员支持 × 删除（ConfirmModal 确认）；**唯独姓名无编辑入口** ✓
- 数据 `[{ name, roles }]` 存于 settings；全站人员选择（款式设计师 SmartSelect / 批次版师·样衣工 / 看板「全部分派设计师」筛选）按 **name 字符串**引用联动（README_DEV 已记录的「字段直接存储 vs ID 引用」架构缺陷范畴）

### 4.3 决策结论（2026-09-09 用户拍板）

**改名后同步更新全站引用**——选项 B：
- 改名时同步更新已落库的引用字段：`styles.designer`（款式设计师）、`sample_runs.pattern_maker`（批次版师）、`sample_runs.sample_maker`（批次样衣工）
- 看板「全部分派设计师」筛选、SmartSelect 联动按 name 实时匹配，数据更新后自动一致
- **不回改**：历史版本快照（task_versions 内 JSON，反映当时状态）、操作日志（operation_logs，历史动作记录）——快照/日志语义即历史快照，不做改写

### 4.4 实施要点

- **后端新增改名接口**：`PATCH /api/people/rename`（body: `{ oldName, newName }`），**事务内**执行：
  1. `settings.people`：JSON 数组中 oldName → newName
  2. `styles.designer = oldName` → newName（UPDATE styles）
  3. `sample_runs.pattern_maker = oldName` → newName（UPDATE sample_runs）
  4. `sample_runs.sample_maker = oldName` → newName（UPDATE sample_runs）
  5. 返回受影响记录数（styles / runs 各计），失败回滚
  - 归属：server/services/settings.cjs（或独立 people 服务）+ routes/settings.cjs；IPC 通道（preload/main/client）若需同步注册
- **前端 PeopleEditor.jsx**：
  - 姓名 span 改为可编辑（点击姓名进入编辑态 input，或悬停铅笔按钮，实现时择优）
  - 提交：Enter / blur 保存（调用 rename 接口）；Escape 取消；重名校验与新增一致（`people.some(p => p.name === v)`，与新增同规则）
  - 保存成功 → onChange 刷新 settings + 通知父级 loadTasks 刷新全站（设计师/版师/样衣工列与筛选随之更新）
  - 列表渲染 key 改用稳定索引（当前用 p.name，改名后 key 变化触发重渲染）
  - 角色操作（添加/删除）、人员删除确认（ConfirmModal）不受影响
- **验证**：HTTP 全链路（改名后 settings/styles/runs 三处引用同步 + 事务回滚）+ 浏览器 E2E（点击进入编辑态/改名保存落库/全站设计师·版师·样衣工显示新名/reload 保持/重名阻止/取消还原/角色与删除功能回归/零 console 错误）+ 生产构建 + 测试数据恢复

### 4.5 实施结果（2026-09-09 已完成）

- 后端：`PATCH /api/people/rename`（settings.cjs `renamePerson` 事务）——settings.people + 遗留 designers 兼容数组 + styles.designer + sample_runs.pattern_maker/sample_maker 同步；重名/不存在/空名拒绝、同名幂等；IPC `settings:renamePerson` 同步注册（main.js / preload.js / client.js）
- 前端：PeopleEditor 姓名可点击编辑（Enter/blur 即改即存、Escape 取消、重名校验与新增一致、列表 key 改稳定索引），改名成功 loadSettings+loadTasks 刷新全站；新增 .people-name-input/.people-name-pen 样式
- 验证：HTTP 27 项 PASS + 浏览器 E2E 17 项 PASS + 生产构建通过（9.0s）；测试数据已恢复（白洁/SS26-DR002/MR.Y 与基线一致）

## 六、开发过程纪律（沿用 AGENTS.md）

1. 改动必须自测通过（真实结果）才能交付，禁止"应该没问题"
2. 数据验证一律走 HTTP fetch（shell node 直连 better-sqlite3 报 ABI 错误，禁止直连）
3. E2E userDataDir 放 %TEMP%（避免 Vite EBUSY 崩溃）；测试脏数据必须清理、用户真实数据恢复原状
4. git add 指定文件，禁止 `git add -A`；不推送测试残留
5. 每完成一步先与用户确认，未确认不擅自进入下一步
6. vite build 必须在真实路径 `D:\dev\golden-shuttle` 下执行（符号链接路径构建报 fileName 错误）
